## Independent findings/contradictions
1. [“Are people working toward the wrong goal?” thread](https://www.kaggle.com/competitions/name-that-llm/discussion/759187) only reports an anonymous second-hand anecdote: somebody allegedly above 0.73, few official submissions, barely any external data. **No public implementation, authenticated receipt, or control for privately trained/pretrained assets**. Cannot infer majority of Code authors are wrong. Separately [“more external data?”](https://www.kaggle.com/competitions/name-that-llm/discussion/749447) contains a top-ten participant saying no **paid generation** (and 'haven't used my credit card'); that does **not** mean no public external corpora or pretrained weights.
2. [Early Qwen layers](https://www.kaggle.com/competitions/name-that-llm/discussion/750462): frozen Qwen3-4B layers 3→0.391 grouped CV, 36→0.311; six-layer concat 0.414; combined with TF-IDF/stylometry, CV 0.439, Public 0.420 by author's report. Crucially **our in-flight Qwen3-1.7B four-layer F1 chooses ¼,½,¾,final** and **omits the strongest early ~8%-depth feature** from this public precedent. Freeze the ongoing F1, do not silently change it mid-run; if warranted, pre-register a separate early-layer extraction or revised layer comparison **after genuine C1/C2 result**, not a circular sweep.
3. [Retrained Qwen2.5-14B member](https://www.kaggle.com/competitions/name-that-llm/discussion/753177): contributor reports OOF 0.569→0.605 but one Public 0.651→0.647; the -0.004 observation alone is below identical-code score variability. Shows real CV/more-data can fail to transfer; does not conclusively prove that exact retraining hurts.
4. [Hungarian structure trap](https://www.kaggle.com/competitions/name-that-llm/discussion/751802): author reported grouped train OOF 0.374→0.481, Public 0.353→0.350. Alex Chilton independent multi-pipeline summary also found +10-ish grouped OOF gains turn to -0.009 to -0.017 Public under clustering/assignment. Hidden grouping and model multiplicity not specified; can't extrapolate TRAIN 149 complete 18-class prompt groups to hidden.
5. [Open Pool cleaned quality](https://www.kaggle.com/competitions/name-that-llm/discussion/753779): author claims fixed sample 45k data and 2 seeds gives +0.026–.027 BA on official TRAIN with source cleaning; **not a hidden Public improvement**. [v14 analysis](https://www.kaggle.com/competitions/name-that-llm/discussion/752766) identifies possible real-vs-proxy generation mismatch for Kimi (reasoning high 25% recognized vs off 8%; real 31%, using train-fitted weak classifier). These are indirect diagnostics, not proof of host's exact generation settings; nevertheless provenance, version and serving mode likely matter more than gross external row count.
6. [NTL sibling pair notebook](https://www.kaggle.com/code/ik786786/name-that-llm-telling-sibling-models-apart) used official TRAIN 150 prompts and grouped CV to compare hard siblings: GPT Sol/Luna .593, Gemini Flash 3.7/3.8 .557, GLM 5.3/Flash .457. Same-prompt matched-pair decisions give higher pair accuracy for some pairs but are not legitimate hidden-test score without true grouping. **Not all mistakes are sibling errors**: [0.704 error map notebook](https://www.kaggle.com/code/asteriospanoras/0-704-which-llms-look-alike-error-map-and-ideas) states 46% of errors of *its simple 0.34 proxy* cross providers (GLM→Claude etc). That proxy does NOT show champion 0.702's residual error distribution; its 0.704 title belongs a separate forked public pipeline, not the charts.
7. [CPU baseline thread](https://www.kaggle.com/competitions/name-that-llm/discussion/760286) gives GroupKFold ~0.32 vs StratifiedKFold ~0.09 on identical baseline — **random splits need not be optimistic**. With complete prompt×model groups, naive row folds can be profoundly pessimistic/misaligned too. Use prompt-grouped splits because hidden prompts are unseen, but never assume the same marginal class/source/serving distribution.
8. [Single-model discussion](https://www.kaggle.com/competitions/name-that-llm/discussion/754860) contains unverified participant claims ~.65–.67 Public with Qwen, some with clearly stated external pretraining. No evidence "one model, official TRAIN only >0.73".
9. [GLM likelihood vs easy style cues](https://www.kaggle.com/competitions/name-that-llm/discussion/757199): author reports their GLM 5.3 / Flash and Claude Fable weak recalls, proxy likelihood of other models and +33k extra data not helpful; actual GLM weights via segment GGUF are a distinctive targeted evidence mechanism but loading 9h offline is a real engineering hurdle.
10. [Alex Chilton 0.702 notebook](https://www.kaggle.com/code/alexchilton/name-that-llm-0-702-all-public-what-failed): not an original self-developed single model; a substantial public pretrained/LoRA/likelihood aggregation. Detailed own ablations show extra members usually flat or worse; same byte-identical code scored as widely as 0.682–0.694 on other versions. Treat +.001–.005 Public as noise until stronger evidence; no base/champion OOF is available.
11. The 0.704 "error map" is a study of a **simple proxy model** (34% 18-class BA, ~70% family classification) paired with an unchanged public 0.704 scoring pipeline; no honest labeled hidden error map for 0.704 was supplied.

## Consequences for our repo
- Official incumbent **0.702 Public (#58514818)** frozen. F1 C0 actual official TRAIN group OOF **0.291509** (not Public). In-flight frozen Qwen3-1.7B F1 GPU action [#44544600364](https://github.com/kolihhan/name-kaggle/actions/runs/44544600364) had not returned terminal C1/C2 when inspected. Do not claim novel gains.
- F1 useful as **theory check**, not a novel architecture invented in a vacuum: early decoder layers already publicly shown to work; the current C1/C2 configuration does not test the earliest layers. Prefer early-layer design only as a new prospective test after current run finishes, not silently changing the running code.
- High priority: build a *calibrated* evaluation ruler that compares matched same-source predictions across progressively sparse prompt groups (1/2/4/18 texts), but explicitly **separate individual row-independent classifier scores (unaffected mechanically by seeing fewer group members)** from grouping/centering/Hungarian methods (change semantics with group size). Validate ranking against externally known Public receipts only when truly comparable; correlations on a few repeatedly-tuned pipelines are fragile.
- **Source provenance & identity**: reject contamination/mislabeled API wrappers, audit reasoning setting and serving versions; test prompt+source-disjoint transfer before scaling external rows. More 18-class rows aren't inherently better.
- **Task-specific expert** evidence should target actual family boundary and sibling confusions separately, with per-class rescues/regressions. A perfect family classifier does not solve within-family; GLM-vs-Claude *cross-provider* confusions cannot be fixed by intra-family gates alone.
- Avoid adaptive inference penalty changes on tiny, reused OOF/Public; do not claim only data-less approach is correct. Infer under competition constraints and preserve official score receipts.

No new scoring, GPU training, external data acquisition or Kaggle submission executed in this audit.
